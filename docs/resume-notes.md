# 简历表述与面试讨论点

这里提供项目表述示例，**需要按本人实际承担的职责调整**。仓库展示的是项目实现，不能据此推定某一位作者独立完成了全部工作。不要将示例中的“实现”直接当作个人贡献证明，也不要补写没有测量或记录的性能、并发、开发周期或用户规模。

## 一段项目介绍

**Live☆Twin Community｜Flask 全栈主题社区与卡片工具**

以游戏王 Live☆Twin / Evil★Twin 为主题，将交互式卡册、社区交流、卡片检索和卡组构筑整合到同一应用中。采用 Flask、Jinja、SQLAlchemy、SQLite 与原生 JavaScript，实现内容与社交业务、OCG 规则一致性、公开资料维护和上游故障回退。

技术栈可写为：`Python / Flask / SQLAlchemy / SQLite / JavaScript / Jinja / GSAP / PWA`。

## 可按职责调整的三条描述

1. 基于 Flask、SQLAlchemy 与原生 JavaScript 实现主题社区，覆盖论坛、私信、收藏关注、通知和卡组分享，围绕 16 个持久化模型组织业务、查询缓存与限速记录。
2. 构建支持多维条件筛选的卡片检索和三区卡组编辑器，实现 OCG 禁限规则读取、同卡异画编号归一及跨分区投入合计，使缓存展示和保存校验使用当前规则。
3. 设计公开卡片资料维护与故障回退链路，整合属性、中文文本和官方禁限来源，加入校验和、完整性检查、明确日期的本地文本快照，以及独占环境下的语义和业务回归验证。

如果实际只负责其中一部分，可以改为“负责卡片检索与规则一致性模块”“参与社区模型与接口实现”“完善资料刷新与测试流程”，并在面试时说明具体改动。

## 适合展开讲的设计选择

### 缓存新鲜度与规则一致性

关键词结果可以缓存，禁限状态却可能在缓存过期前变化。项目将卡片结果和当前规则读取分开，在返回缓存时重新计算禁限；保存端使用同一份规则语义。

可以讨论：为什么仅缩短缓存 TTL 仍不足以解决显示/保存不一致？为什么要避免直接修改缓存中的原始结果？

### 同一卡片的不同编号

主图号、官方密码与异画编号可能不同。项目保留用户选择的图号，用规范 ID 合计投入上限，兼顾展示与校验。

可以讨论：映射为什么应为扁平关系？如何拒绝链式、循环或冲突映射？为什么主/额/副三处必须一起计数？

### 上游不可用时如何诚实降级

上游失败时，不把错误变成“没有结果”，也不把本地旧资料冒充实时结果。已有关键词缓存和本地原文快照有明确优先级，页面显示状态与日期。

可以讨论：为什么本地回退不应写入远端关键词缓存？怎样避免故障恢复后仍长时间使用回退结果？

### 数据完整性与落盘边界

刷新管线在写入前验证来源、ID、数量和名单关联，输出逐文件原子替换。它保护单个文件，但不提供整套数据事务。

可以讨论：为什么 MD5 要作用于解压 JSON？如何识别错误分页或异常缩减？在线更新多文件快照需要怎样的切换机制？

### 测试为什么需要真正隔离

业务冒烟可能建表、写入或清理文件。仅替换数据库 URL 并不足以隔离上传、词表和日志，项目使用独占源码副本与临时目录运行。

可以讨论：如何证明测试没有访问真实业务文件？哪些验证可以离线完成，哪些必须依赖真实浏览器或网络？

## 不建议使用的说法

- “支持高并发/百万级访问”“性能提升若干倍”：没有相应压测证据。
- “完整赛事合法性校验”：目前未全面校验卡片存在性、卡种分区和发售状态。
- “所有卡片/整个论坛完全离线可用”：PWA覆盖应用壳和已缓存的静态资源。
- “全部中文名都是官方译名”：快照明确区分官方简中与社区译名。
- “零副作用的纯应用工厂”“完整自动数据库迁移”：当前入口导入时初始化应用与表，已有表结构需单独迁移。
- “企业级安全”“已通过全面安全认证”：实现具体保护机制不等于获得安全认证。
- “一个人从零独立完成”“若干天完成”：只有本人实际职责和记录能支持这样的表述。
